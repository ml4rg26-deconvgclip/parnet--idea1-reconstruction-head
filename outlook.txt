1. THE CORE PROBLEM
--------------------------------------------------------------------------------
The reconstruction loss only ever sees the AGGREGATE globalCLIP signal,
never the contributions of individual proteins. This creates a real
identifiability problem: if two proteins (e.g. PTBP1, PTBP2, PUF60) have
strongly correlated, similar Parnet tracks, the model can shift weight
between them arbitrarily without the reconstructed signal changing
measurably. The training loss is blind to this ambiguity — it cannot
distinguish "correct" attribution from "numerically equivalent but wrong"
attribution.

Partial solution already in place: the log-amplitude s_k is fixed per
protein across ALL windows/positions (not relearned per window) — this
prevents window-level overfitting, but does NOT solve the risk of confusing
different, but correlated, proteins with each other. This is the actual
reason QLayer was originally developed: the phase-interference mechanism
was meant to give correlated proteins a distinguishable "fingerprint" via
the cross-terms with all 222 other proteins — structure a plain linear sum
cannot represent.

QLayer/CombiLayer have not demonstrably solved this so far, though:
statistically tied with CNN-only on accuracy (within 0.007 Pearson), and
the coupling-matrix analysis is still inconclusive (only cooperative, no
competitive couplings found; expected validation proteins such as
spliceosome components U2AF1/U2AF2, SF3B4, PRPF8 are missing from the
dominant proteins) — and it has so far only been run on an earlier model
version, not on the final filtered checkpoints.


2. NEW IDEA FROM THE CALL: EMPIRICAL CORRELATION AS AN INDEPENDENT CHECK
--------------------------------------------------------------------------------
Proposal: instead of just hoping QLayer's learned coupling matrix reflects
real protein-protein cooperation, check it INDEPENDENTLY — directly from
the raw, uncombined Parnet tracks, with no training loss or mixing weights
involved at all:

  For every protein pair (i, j): compute the correlation between
  track_i(p) and track_j(p) across all positions p, and across many
  training windows.

This "raw" correlation is not ambiguous — it's based only on Parnet's own
independent per-protein predictions, before any combination happens. High
correlation = the two proteins consistently predict high values at the same
positions = genuine evidence of co-occurrence (cooperation), or of
confusability risk.

TWO POSSIBLE WAYS TO USE THIS:

  (a) Validation / diagnostic (recommended as the FIRST step):
      Compute the raw track-correlation matrix (no retraining needed, just
      a computation on existing checkpoints/data) and compare it against
      QLayer's learned coupling matrix (cos(phase_i - phase_j)). If they
      agree → strong, independent evidence that QLayer's phase mechanism
      learned genuine structure, not noise. If they DON'T agree → likely
      explains why the interaction analysis has been inconclusive so far
      (see section 1).

  (b) Explicit loss term (only if (a) shows a discrepancy):
      Add the raw correlation matrix as an additional training target that
      pulls the learned coupling matrix toward the empirical co-activity —
      giving the model real supervision on interaction structure, instead
      of hoping it falls out of the pure reconstruction loss. Cost: a new
      hyperparameter (weighting against the Pearson/NLL/sparsity terms
      already present), requires retraining, adds complexity.

RECOMMENDATION: do (a) first, only do (b) if actually needed.
  - (a) is essentially free: no retraining, doable immediately with
    existing checkpoints/data, gives an answer this week.
  - (a) is diagnostic BEFORE it's corrective: right now we don't know
    whether the coupling matrix reflects real signal or noise — this check
    answers that directly, before investing effort in a new loss term.
  - Only if (a) shows the learned coupling matrix does NOT match the raw
    correlation is (b) worth the effort — at that point we'd know the pure
    reconstruction loss genuinely isn't enough and explicit supervision is
    needed.


3. FURTHER OPEN ITEMS (from earlier discussions, still valid)
--------------------------------------------------------------------------------
- Re-run the QLayer/CombiLayer coupling-matrix analysis on the final,
  outlier-filtered checkpoints (current results are from an earlier model
  version and not yet final).
- Stability selection / ensemble: compare multiple independent training
  runs (different seeds or bootstrap resamples) and only trust proteins
  whose high weighting is consistent across runs — addresses the observed
  instability (global vs. positional mixing give completely different
  top-5 proteins).
- Test control-track normalization empirically after all (Lysate_noNHS
  etc.) — could strip out shared background and sharpen protein-specific
  signal, even though its suitability hasn't been officially confirmed.
- Biologically informed grouping: use known protein complexes (spliceosome,
  EJC, hnRNP family, from STRING-DB or literature) as a structural prior to
  reduce the degrees of freedom in the 223 weights and make attribution
  more structurally identifiable, instead of learning everything freely.
- Additionally validate the coupling matrix against independent
  protein-interaction databases (STRING-DB), not just motif databases.
- Normalize the motif-detection significance threshold onto a comparable
  scale between the 7M and 21M backbones, to check whether the stronger
  fragmentation seen with the 21M backbone is a real effect or just an
  artifact of different IG attribution scales.
- Generate consensus-motif letter-code plots for the refined Idea-1 models
  (needs the server: RBP motif database + metamotif tool not available
  locally).


4. KEY TAKEAWAY FOR THE OUTLOOK
--------------------------------------------------------------------------------
Best predictive accuracy (highest Pearson r) and best protein-level
interpretability are two separate goals that, in this project so far, move
in opposite directions (21M backbone: best predictor, weakest motif/
interaction resolution). The right next step is not to throw more capacity
or architectural complexity at the accuracy objective, but to deliberately
add information the pure reconstruction loss is missing — first and
foremost, the raw, uncombined protein correlation as a signal for genuine
cooperation between proteins.


5. EXTERNAL REVIEW CROSS-CHECK (2026-07-15): SHORTCUT LEARNING / GLOBAL-MIXING BIAS
--------------------------------------------------------------------------------
An external second-opinion review diagnosed the Pearson-inflation issue as shortcut
learning: global positional mixing lets the model absorb RNA-abundance / expression
background into the reconstructed signal instead of learning real, local RBP motifs
(motifs get "smeared" and sigmoid-saturated). First cross-checked against the code
in project-parnet/src/globalclip_utils/{model,training_utils}.py; then re-checked
against project-parnet/README.md, which turns out to already contain the final,
outlier-filtered test-set numbers and its OWN "Outlook" section — a more complete
and more current document than this file for items 1-4 above (see note at the end).
That numeric evidence changes the priority of a few of the items below; corrected
version:

5a. ALREADY IN PLACE, AND ALREADY EMPIRICALLY CONFIRMED — no action needed
  - The review's core diagnosis (global mixing lets background/abundance leak into
    the prediction) is not just architecturally addressed, it is already this
    project's single most validated finding. README.md's Findings table shows
    switching MixCoeffHead from global (mean-pool embedding over the full 600nt,
    one alpha per sequence) to positional (`positional_alpha=True`, per-position,
    kernel_size=1, zero cross-position context) gave the largest accuracy jump
    anywhere in the project: Standard model 0.264 -> 0.429 (+0.165 r), and the same
    direction for CNN-only (0.427 -> 0.442) and QLayer (0.407 -> 0.439). README
    calls this "the single biggest architectural bottleneck ... larger than any
    refinement architecture tested afterward" and every documented training command
    already defaults to `--positional-alpha`. So this isn't a hypothesis to test —
    it was already tested, at the two extremes (full-window vs. zero-context), and
    zero-context won decisively.
  - Pyramidal dilation (1, 2, 4, ...) in the post-QLayer CNN (model.py,
    GlobalCLIPQLayerModel.__init__, `dil = 2 ** i`) already matches the "first layer
    dilation=1, deepen gradually" recommendation. Its receptive field is only
    roughly 55-60nt (kernel=9, 3 layers).
  - The final prediction is NOT sigmoid-squashed. `pred` is a raw regression output
    trained against log1p(signal) via Pearson+NLL loss. The only sigmoid sits inside
    MixCoeffHead on the per-protein alpha mixing weights (a 0-1 mixing coefficient by
    design), not on the final signal amplitude — so "desaturate the output sigmoid"
    doesn't apply the way the review assumed.
  - multinomial_nll_loss already normalizes over the sequence via log_softmax, which
    achieves the same purpose as the review's "divide by outputs.sum()" suggestion.
  - A working motif-quality check already exists and has already been run once:
    `motif_validation.py` runs Integrated Gradients directly on PARNET's own frozen
    per-protein tracks and checks each protein's recovered motif against its
    literature motif ("self-match"), independent of any combi-layer mixing weights.
    README Findings #4: 7M backbone self-matches 6/15 top-weighted proteins vs. only
    2/15 for the 21M backbone (3.27 vs. 2.33 consensus motifs/protein). So "does the
    model actually find real motifs" is not an open question needing new tooling —
    it's already measured; see 5b for what's still missing (using it *during*
    training, not just post-hoc).

5b. GENUINELY NEW, BUT RE-PRIORITIZED AGAINST THE ABOVE EVIDENCE
  - Windowed mixing (Conv1d with a real kernel, e.g. ~101nt, in MixCoeffHead, as a
    middle ground between global-mean-pool and zero-context positional) is still
    unimplemented and still a legitimate experiment — but LOW priority, not high:
    the zero-context extreme already beat the full-window extreme by the largest
    margin in the whole project (5a), so there's no existing evidence a partial
    window would help further, and it could just as easily reintroduce some of the
    averaging that hurt in the first place. Only worth trying if someone specifically
    wants to explain the remaining global/positional top-5 protein instability
    (section 3) as a smoothing question rather than as an identifiability question.
  - Residual/delta learning against the frozen backbone's own combined signal is
    still unimplemented and still a reasonable small experiment for stripping
    expression bias before combining — but temper expectations: README Findings #5
    notes a Poisson counting-noise ceiling on this data (best raw result r=0.476,
    r^2=0.23; smoothing to ~50bp lifts the practical ceiling to only ~0.65-0.70).
    Any bias-removal trick is bounded by that same ceiling, not just by architecture.
  - A ranking loss (e.g. margin ranking on local peak order) alongside or instead of
    part of the Pearson loss is still unimplemented and still a good fit for this
    outlook's own section 4 takeaway ("add information the pure reconstruction loss
    is missing") — nothing in README's numbers argues against trying it.
  - Wiring `motif_validation.py`'s self-match check into the training loop as an
    early-stopping / model-selection signal (instead of only running it once,
    post-hoc, per README Findings #4) is the part of the "motif-based early
    stopping" idea that's actually still open. Same constraint as the consensus-motif
    plots in section 3: needs the RBP motif database + metamotif tool, server-only.

5c. REVIEW POINTS THAT DON'T MAP CLEANLY ONTO THIS CODEBASE — needs reframing
  - BCEWithLogitsLoss was recommended to replace sigmoid+Pearson, assuming the model
    predicts binary peak/no-peak labels. It doesn't: the target is continuous
    log1p(read-count) regression, and there are no binary peak labels in the dataset
    to supervise a BCE loss against. The ranking loss in 5b is the closer fit to what
    the review is actually after (sharper, less-smeared peaks) without needing
    labels we don't have.
  - The QLayer "potential regularization" / wavefunction-delocalization suggestion
    assumes QLayer solves a spatial Schrodinger-type equation with a potential term.
    It doesn't — QLayer (model.py) is a per-protein *phase* interference layer
    (phi_i is a scalar, or per-position via positional_phase, per protein; no
    potential, no finite-differences PDE solve). The closest existing lever is the
    `lambda_phase` phase regularization already in training_utils.py, not a new
    potential term.
